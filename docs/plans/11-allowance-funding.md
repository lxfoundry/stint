# Stage 11: Allowance Funding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or
> executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** A session can be funded from an allowance. An owner grants the agent's key a recurring delegation on the
Solana Foundation's Subscriptions & Allowances program (`De1egAFMkMWZSN5rYXRj9CAdheBamobVNubTsi9avR44`). Every open and
every top-up then pulls its deposit from the owner's USDC account into the session's vault, in the same transaction as
`stint.open` or `stint.top_up`, signed by the agent as the delegation's delegatee. Refunds go back to the owner. The
program enforces the cap per period on-chain: a pull over it fails, and the payment is refused. Scenario 12 passes on
`local` and becomes `required`, and it passes on devnet with the other required scenarios. **No program change: the
deployed program is not upgraded.**

**Architecture:** A new workspace package, `packages/subscriptions-client`, holds a client for the Subscriptions
program. It is generated by Codama from the program's IDL, which is vendored at a pinned commit, plus a few helpers:
- the accounts of a delegation;
- the period maths, mirroring the program's;
- the grant and revoke instructions;
- the pull.

The rest of the stage:
- **Scheme:** a funding source, either the authority's own account or an allowance; its builders write the pull
  instead of `TransferChecked`. Its static checks accept one pull as the funding instruction and check it the way the
  program will (spec section 10.2).
- **Facilitator:** after simulation, it checks that the vault receives exactly `amount`, counting inner transfers, and
  names the allowance in its refusal messages.
- **Client:** an `allowance` option, a check before signing when it has a node, a report of the period, the
  `stint_allowance` tool and its MCP settings, and the `stint allowance grant | revoke | status` command for owners.
- **Harness:** a grant fixture on both targets, the devnet clean-up of delegations, and scenario 12.

**Tech Stack:** TypeScript 7.0.2, vitest 5.0.5, `@solana/kit` 8.5.0 with `@solana/program-client-core` 8.5.0,
Codama 1.11.0 with `@codama/renderers-js` 2.8.0, Surfpool 1.6.1, Kora 2.0.5.

## Global Constraints

- Platform: Linux x86-64; on Windows, everything runs inside WSL 2. Run every command from the repository root,
  inside WSL. Keep scratch files under the home directory or a git-ignored folder of the repository, not `/tmp`.
- **Devnet only.** No transaction from this repository's code or scripts reaches another network. The
  `stint allowance` command checks devnet's genesis hash before it sends anything, as the harness does.
- Transactions are version 0, without address lookup tables (spec section 3.5). Only classic SPL Token mints; the
  payment token is devnet USDC, `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`, 6 decimals (spec section 3.4).
- `u64` values on the wire are decimal strings; amounts are `bigint` in TypeScript, never `number`.
- **No secrets, ever, in any commit.** Keypair files are named by path; never print a key's contents. An RPC URL may
  carry an API key: never print one.
- **A refund goes back to the account the money came from** (spec section 4.6). With an allowance, that is the owner's
  associated token account, so `refund_owner` is the owner, in the open and for every top-up.
- **The delegatee is the session's authority** (spec section 10.2). The pull is signed by the agent's key, which is the
  key that signs `stint.open` and `stint.top_up`. No other key signs a pull.
- Every spending limit of the client's policy still applies in allowance mode (spec section 9.3). The allowance's cap is
  enforced on-chain on top of it, not instead of it.
- The Subscriptions program's client is generated, never edited by hand. Its IDL is vendored at the commit named in
  `packages/subscriptions-client/idl/README.md`, with the program's MIT licence beside it.
- Scenario statuses follow the ratchet of spec section 12.2: scenario 12 is made `required` in the commit where it
  first passes on `local`, and never goes back to `pending`.
- Test first: write the failing test, run it, implement, run it again, commit.
- Commit messages are neutral, technical and in the present tense.

**Built:**

- the facilitator's check that the vault receives exactly `amount`;
- the client's `allowance` option, its check before signing (with `rpc`), its period report, the `stint_allowance`

- the harness's grant fixture on `local` and `devnet`, and the devnet clean-up of delegations;
- spec section 14, question 6, completed with a real pull;
- scenario 12.

**Not built:**
- **Our program as the delegatee,** so that an allowance could only fund sessions. That needs the Stint program to call
  the Subscriptions program, which that program does not document. The delegatee is the agent's key. Its exposure is the
  period's cap until the delegation is revoked or expires (spec section 10.3).
- **Fixed delegations and subscriptions** (the program's `transferFixed` and `transferSubscription`). Only a recurring
  delegation funds a session; any other instruction of the program is refused as `unexpected_instruction`.
- **Token-2022 mints and transfer hooks.** A pull with more than its nine accounts is refused.
- **A sponsored grant.** The owner pays the rent of the grant's two accounts and its fee, in SOL.
- **Allowance funding in `DirectChain`** (sessions opened straight on the program). No scenario needs it.
- **What a session spent per period.** The client reports what was pulled in the period (which a refund does not
  lower), what is left and when the period ends. Spec section 10.3 is reworded to say exactly that.

## How a pull works (read before Task 1)

Facts from the program at tag `ts-client-v0.5.0` (commit `5a347ffaa969036061d274d3c91e0277962e2b51`, program version
0.5.0). The program runs from the copy the harness already loads (`e2e/.cache/subscriptions.so`, sha256
`2675ad1d2b5068d47fc5d169156cf4859a9c21c0406ce63e3828e3b7320fddbf`, dumped from devnet).

**The grant** is one transaction, signed by the owner, who pays the fee and the rent of two accounts:
- `initSubscriptionAuthority` (instruction 0): creates the owner's Subscription Authority PDA for the mint,
  `["SubscriptionAuthority", owner, mint]`. It approves that PDA as the SPL Token delegate of the owner's associated
  token account, for `u64::MAX`. That account then has no other delegate (S8).
- `createRecurringDelegation` (instruction 2): creates the delegation PDA,
  `["delegation", subscriptionAuthority, owner, agent, nonce as u64 LE]`. Its data:
  - `nonce`, `amountPerPeriod`, `periodLengthS`;
  - `startTs`: `0` means "start when this lands", and then needs a non-zero `expiryTs`;
  - `expiryTs`;
  - `expectedSubscriptionAuthorityInitId`: `i64::MIN` (`UNKNOWN_INIT_ID`) when the authority is created in the same
    transaction; the authority's stored `initId` otherwise.

**The pull** is `transferRecurring` (instruction 5).
- **Data:** `{ amount u64, delegator, mint }`.
- **Accounts, in order:**
  1. `delegationPda` (writable)
  2. `subscriptionAuthority`
  3. `delegatorAta` (writable)
  4. `receiverAta` (writable)
  5. `tokenMint`
  6. `tokenProgram`
  7. `delegatee` (signer)
  8. `eventAuthority` (`["event_authority"]`)
  9. `selfProgram`
- **What it does:** it advances the period if one has elapsed, adds `amount` to `amountPulledInPeriod`, and moves the
  tokens with a `TransferChecked` signed by the Subscription Authority. It then emits an event through a call to
  itself. It moves no lamports and creates no account.
- **What it checks:**
  - that `delegatorAta` is the canonical associated token account of `delegator`;
  - only the mint of `receiverAta`, so the vault must already exist (the open creates it in the instruction before).
- **Errors:**
  - `0x190` (400, `amountExceedsPeriodLimit`): the pull would go over the period's cap;
  - `0x80` (128, `delegationExpired`): after `expiryTs`;
  - `0x197` (407, `delegationNotStarted`): before the period's start.

**The period** rolls over lazily, at the next pull:
- if at least one period has elapsed since `currentPeriodStartTs`, the start advances by whole periods, and the amount
  pulled goes back to 0;
- with a finite expiry, it advances only to the last period start before the expiry;
- `periodState` in Task 1 mirrors this rule exactly.

**Revoking:**
- `revokeDelegation` (instruction 3, signed by the owner) closes the delegation, and its rent returns to the owner;
- `closeSubscriptionAuthority` (instruction 6, signed by the owner) closes the authority, and its rent returns too;
- closing the authority breaks every other delegation of that owner and mint, so the `stint allowance revoke` command
  does it only when asked.

**A refund does not restore the allowance.** The program counts pulls, so `amountPulledInPeriod` is unchanged by a
close that refunds the owner.

**What was observed** on the local stack, before this plan: a grant, an open and a top-up, each pulled from the owner
and co-signed by Kora with the harness's allowlist (which already includes the Subscriptions program). Kora's own
simulation refused an open over the cap with `custom program error: 0x190`. The grant cost the owner 3,993,080 lamports.

  periodLengthS: 100n,

describe("periodState: the program's rule for the next pull", () => {
  it("leaves a period alone while it runs", () => {
    expect(periodState(delegation(), 1_050n)).toEqual({
      perPeriod: 500n,
      pulled: 200n,
      available: 300n,
      periodStart: 1_000n,
      periodEnd: 1_100n,
      expiresAt: 0n,
      status: "active",
    });
  });

  it("starts a new period with nothing pulled once one has elapsed, skipping whole periods", () => {
    expect(periodState(delegation(), 1_100n)).toMatchObject({ periodStart: 1_100n, pulled: 0n, available: 500n, periodEnd: 1_200n });
    expect(periodState(delegation(), 1_350n)).toMatchObject({ periodStart: 1_300n, pulled: 0n });
  });

  it("advances no further than the last period start before a finite expiry, and ends that period at the expiry", () => {
    // Expiry 1,300: at 1,300 the next boundary is the expiry itself, so the period that started at 1,200 is the last.
    expect(periodState(delegation({ expiryTs: 1_300n }), 1_300n)).toMatchObject({
      periodStart: 1_200n,
      periodEnd: 1_300n,
      pulled: 0n,
      status: "active",
    });
    expect(periodState(delegation({ expiryTs: 1_250n }), 1_240n)).toMatchObject({ periodStart: 1_200n, periodEnd: 1_250n });
  });

  it("offers nothing after the expiry, a hard stop, or before the period's start", () => {
    expect(periodState(delegation({ expiryTs: 1_250n }), 1_250n).status).toBe("active");
    expect(periodState(delegation({ expiryTs: 1_250n }), 1_251n)).toMatchObject({ status: "expired", available: 0n });
    expect(periodState(delegation(), 999n)).toMatchObject({ status: "notStarted", available: 0n });
  });

  it("never reports less than nothing left", () => {
    expect(periodState(delegation({ amountPulledInPeriod: 600n }), 1_050n).available).toBe(0n);
  });
});

describe("the accounts and instructions of an allowance", () => {
  it("derives the program's PDAs and the owner's associated token account", async () => {
    const owner = (await generateKeyPairSigner()).address;
    const agent = (await generateKeyPairSigner()).address;
    const accounts = await allowanceAccounts({ owner, agent, mint: MINT, nonce: 7n });
    const key = getAddressEncoder();
    const [authority] = await getProgramDerivedAddress({
      programAddress: SUBSCRIPTIONS_PROGRAM_ADDRESS,
      seeds: ["SubscriptionAuthority", key.encode(owner), key.encode(MINT)],
    });
    const [delegationPda] = await getProgramDerivedAddress({
      programAddress: SUBSCRIPTIONS_PROGRAM_ADDRESS,
      seeds: ["delegation", key.encode(authority), key.encode(owner), key.encode(agent), getU64Encoder().encode(7n)],
    });
    const [ownerToken] = await findAssociatedTokenPda({ owner, mint: MINT, tokenProgram: TOKEN_PROGRAM_ADDRESS });
    expect(accounts).toEqual({ subscriptionAuthority: authority, delegation: delegationPda, ownerToken });
  });

  it("pulls exactly the amount from the owner's account into the destination, signed by the agent as delegatee", async () => {
    const agent = await generateKeyPairSigner();
    const owner = (await generateKeyPairSigner()).address;
    const vault = (await generateKeyPairSigner()).address;
    const ix = await allowancePullInstruction({ owner, agent, mint: MINT, nonce: 0n, destination: vault, amount: 30_000n });
    expect(ix.programAddress).toBe(SUBSCRIPTIONS_PROGRAM_ADDRESS);

import { TOKEN_PROGRAM_ADDRESS, findAssociatedTokenPda } from "@solana-program/token";
import type { Address, Instruction, TransactionSigner } from "@solana/kit";
import type { RecurringDelegation } from "./generated/accounts/recurringDelegation.js";
import { getCloseSubscriptionAuthorityInstruction } from "./generated/instructions/closeSubscriptionAuthority.js";
import { getCreateRecurringDelegationInstruction } from "./generated/instructions/createRecurringDelegation.js";
import { getInitSubscriptionAuthorityInstructionAsync } from "./generated/instructions/initSubscriptionAuthority.js";
import { getRevokeDelegationInstruction } from "./generated/instructions/revokeDelegation.js";
import { getTransferRecurringInstructionAsync } from "./generated/instructions/transferRecurring.js";
import { findRecurringDelegationPda } from "./generated/pdas/recurringDelegation.js";
import { findSubscriptionAuthorityPda } from "./generated/pdas/subscriptionAuthority.js";

/**
 * `expectedSubscriptionAuthorityInitId` for a delegation created in the same transaction as the owner's Subscription
 * Authority: the program then requires that the authority was created in the current slot.
 */
export const UNKNOWN_INIT_ID = -(2n ** 63n);

/** A recurring delegation from `owner` to `agent`, for `mint`. `nonce` tells apart two delegations between the same keys. */
export interface AllowanceRef {
  readonly owner: Address;
  readonly agent: Address;
  readonly mint: Address;
  readonly nonce: bigint;
}

export interface AllowanceAccounts {
  /** The owner's Subscription Authority for the mint: the SPL Token delegate of `ownerToken`. */
  readonly subscriptionAuthority: Address;
  readonly delegation: Address;
  /** The owner's associated token account: what a pull debits, and where refunds go. */
  readonly ownerToken: Address;
}

export async function allowanceAccounts(ref: AllowanceRef): Promise<AllowanceAccounts> {
  const [subscriptionAuthority] = await findSubscriptionAuthorityPda({ user: ref.owner, tokenMint: ref.mint });
  const [delegation] = await findRecurringDelegationPda({
    subscriptionAuthority,
    delegator: ref.owner,
    delegatee: ref.agent,
    nonce: ref.nonce,
  });
  const [ownerToken] = await findAssociatedTokenPda({ owner: ref.owner, mint: ref.mint, tokenProgram: TOKEN_PROGRAM_ADDRESS });
  return { subscriptionAuthority, delegation, ownerToken };
}

/** Where a recurring delegation stands, at a time on the chain's clock, as the program's next pull would see it. */
export interface PeriodState {
  readonly perPeriod: bigint;
  /** What has been pulled in the current period. A refund does not lower it. */
  readonly pulled: bigint;
  /** What a pull may still take in the current period: 0 once expired, or before the start. */
  readonly available: bigint;
  /** Unix seconds. */
  readonly periodStart: bigint;
  /** Unix seconds: the next period's start, or the expiry if that comes first. */
  readonly periodEnd: bigint;
  /** Unix seconds; 0 for a delegation that never expires. */
  readonly expiresAt: bigint;
  readonly status: "active" | "expired" | "notStarted";
}

type PeriodFields = Pick<RecurringDelegation, "currentPeriodStartTs" | "periodLengthS" | "expiryTs" | "amountPerPeriod" | "amountPulledInPeriod">;

/**
 * The program's own rule (its `validate_recurring_transfer`), applied at `now` without pulling anything. A period that has
 * elapsed is replaced by the current one, with nothing pulled; with a finite expiry, the start advances no further than
 * the last period start before the expiry. The expiry is a hard stop: after it, nothing can be pulled.
 */
export function periodState(delegation: PeriodFields, now: bigint): PeriodState {
  const length = BigInt(delegation.periodLengthS);
  const expiry = delegation.expiryTs;
  let start = delegation.currentPeriodStartTs;
  let pulled = delegation.amountPulledInPeriod;
  const status = expiry !== 0n && now > expiry ? "expired" : now < start ? "notStarted" : "active";
  if (status === "active" && length > 0n && now - start >= length) {
    const candidate = start + ((now - start) / length) * length;
    if (expiry === 0n || candidate < expiry) {
      start = candidate;
      pulled = 0n;
    } else {
      const lastBillable = expiry - 1n;
      if (lastBillable >= start) {
        const lastStart = start + ((lastBillable - start) / length) * length;
        if (lastStart > start) {
          start = lastStart;
          pulled = 0n;
        }
      }
    }
  }
  const left = delegation.amountPerPeriod > pulled ? delegation.amountPerPeriod - pulled : 0n;
  const end = start + length;
  return {
    perPeriod: delegation.amountPerPeriod,
    pulled,
    available: status === "active" ? left : 0n,
    periodStart: start,
    periodEnd: expiry !== 0n && end > expiry ? expiry : end,
    expiresAt: expiry,
    status,
  };
}

/**
 * One pull of exactly `amount` from the owner's associated token account into `destination` (spec §10.2), signed by the
 * agent as the delegation's delegatee. `destination` must exist: the program checks its mint.
 */
export async function allowancePullInstruction(input: {
  readonly owner: Address;
  readonly agent: TransactionSigner;
  readonly mint: Address;
  readonly nonce: bigint;
  readonly destination: Address;
  readonly amount: bigint;
}): Promise<Instruction> {
  const accounts = await allowanceAccounts({ owner: input.owner, agent: input.agent.address, mint: input.mint, nonce: input.nonce });
  return getTransferRecurringInstructionAsync({
    delegationPda: accounts.delegation,
    subscriptionAuthority: accounts.subscriptionAuthority,
    delegatorAta: accounts.ownerToken,
    receiverAta: input.destination,
    tokenMint: input.mint,
    tokenProgram: TOKEN_PROGRAM_ADDRESS,
    delegatee: input.agent,
    transferData: { amount: input.amount, delegator: input.owner, mint: input.mint },
  });
}

export interface GrantInput {
  readonly owner: TransactionSigner;
  readonly agent: Address;
  readonly mint: Address;
  readonly perPeriod: bigint;
  readonly periodSeconds: bigint;
  /** Unix seconds, after the grant lands. Required: a delegation that starts when it lands must have an expiry. */
  readonly expiresAt: bigint;
  readonly nonce: bigint;
  /** The `initId` of the owner's Subscription Authority if it exists; omitted, the grant creates it. */
  readonly existingInitId?: bigint;
}

/**
 * The grant of spec §10.1: the owner's Subscription Authority, unless it exists, and a recurring delegation to the agent
 * that starts when the transaction lands. The owner signs, and pays the fee and both accounts' rent.
 */
export async function grantInstructions(input: GrantInput): Promise<Instruction[]> {
  if (input.expiresAt <= 0n) throw new RangeError("A grant needs an expiry: a delegation that starts when it lands must end");
  const accounts = await allowanceAccounts({ owner: input.owner.address, agent: input.agent, mint: input.mint, nonce: input.nonce });
  const create = getCreateRecurringDelegationInstruction({
    delegator: input.owner,
    subscriptionAuthority: accounts.subscriptionAuthority,
    delegationAccount: accounts.delegation,
    delegatee: input.agent,
    recurringDelegation: {
      nonce: input.nonce,
      amountPerPeriod: input.perPeriod,
      periodLengthS: input.periodSeconds,
      startTs: 0n,
      expiryTs: input.expiresAt,
      expectedSubscriptionAuthorityInitId: input.existingInitId ?? UNKNOWN_INIT_ID,
    },
  });
  if (input.existingInitId !== undefined) return [create];
  const init = await getInitSubscriptionAuthorityInstructionAsync({
    owner: input.owner,
    tokenMint: input.mint,
    userAta: accounts.ownerToken,
    tokenProgram: TOKEN_PROGRAM_ADDRESS,
  });
  return [init, create];
}

/**
 * Revokes a delegation; its rent returns to the owner. `closeAuthority` also closes the owner's Subscription Authority,
 * which returns its rent too, and ends every other delegation the owner has granted for that mint.
 */
export function revokeInstructions(input: {
  readonly owner: TransactionSigner;
  readonly delegation: Address;
  readonly closeAuthority?: Address;
}): Instruction[] {
  const revoke = getRevokeDelegationInstruction({ authority: input.owner, delegationAccount: input.delegation });
  if (input.closeAuthority === undefined) return [revoke];
  return [revoke, getCloseSubscriptionAuthorityInstruction({ user: input.owner, subscriptionAuthority: input.closeAuthority })];
}

/** A funding instruction, read the same way whatever its kind (spec §5.3, §10.2). */
export interface FundingRead {
  readonly kind: "transfer" | "allowance";
  /** The token account debited. */
  readonly source: Address;
  readonly destination: Address;
  readonly mint: Address;
  readonly amount: bigint;
  /** The key whose signature moves the tokens: the transfer's authority, or the pull's delegatee. */
  readonly signer: Address;
  /** The pull's delegator, the owner of the allowance: an allowance only. */
  readonly owner?: Address;
}

/** The pull's accounts: delegation, subscription authority, owner's account, destination, mint, token program, delegatee, event authority, program. */
const PULL_ACCOUNTS = 9;

function kindOf<T>(identify: (ix: { data: Uint8Array }) => T, ix: Instruction): T | undefined {
  if (!isInstructionWithData(ix) || !isInstructionWithAccounts(ix)) return undefined;
  try {
    return identify(ix as never);
  } catch {
    return undefined; // data no instruction of that program has
  }
}

/**
 * The funding instruction of an open or a top-up: a `TransferChecked`, or one pull from a recurring delegation (spec §10.2).
 * Undefined when the instruction is neither, or is malformed, which the layout check refuses as `unexpected_instruction`.
 * A pull whose program-derived accounts are not the canonical ones for its owner and mint is refused here. Its delegation
 * account is checked by the program itself, at simulation: it holds the delegator and the delegatee the program compares.
 */
export async function readFunding(ix: Instruction): Promise<Check<FundingRead> | undefined> {
  if (ix.programAddress === TOKEN_PROGRAM_ADDRESS && kindOf(identifyTokenInstruction, ix) === TokenInstruction.TransferChecked) {
    try {
      const t = parseTransferCheckedInstruction(ix as never);
      return {
        ok: true,
        value: {
          kind: "transfer",
          source: t.accounts.source.address,
          destination: t.accounts.destination.address,
          mint: t.accounts.mint.address,
          amount: t.data.amount,
          signer: t.accounts.authority.address,
        },
      };
    } catch {
      return undefined; // too few accounts, or short data
    }
  }
  if (ix.programAddress !== SUBSCRIPTIONS_PROGRAM_ADDRESS) return undefined;
  if (kindOf(identifySubscriptionsInstruction, ix) !== SubscriptionsInstruction.TransferRecurring) return undefined;
  // Exactly its nine accounts: more are for a mint's transfer hook, and only classic SPL Token mints are supported (spec §3.4).
  if ((ix.accounts?.length ?? 0) !== PULL_ACCOUNTS) return undefined;
  let pull: ReturnType<typeof parseTransferRecurringInstruction>;
  try {
    pull = parseTransferRecurringInstruction(ix as never);
  } catch {
    return undefined;
  }
  const { accounts, data } = pull;
  const { mint, delegator: owner, amount } = data.transferData;
  const [authority] = await findSubscriptionAuthorityPda({ user: owner, tokenMint: mint });
  const [eventAuthority] = await findEventAuthorityPda();
  if (
    accounts.tokenMint.address !== mint ||
    accounts.tokenProgram.address !== TOKEN_PROGRAM_ADDRESS ||
    accounts.subscriptionAuthority.address !== authority ||
    accounts.eventAuthority.address !== eventAuthority ||
    accounts.selfProgram.address !== SUBSCRIPTIONS_PROGRAM_ADDRESS
  ) {
    return refuse("invalid_terms", "the allowance pull's accounts are not the canonical ones for its owner and mint");
  }
  return {
    ok: true,
    value: {
      kind: "allowance",
      source: accounts.delegatorAta.address,
      destination: accounts.receiverAta.address,
      mint,
      amount,
      signer: accounts.delegatee.address,
      owner,
    },
  };
}

    return { source: t.accounts.source.address, destination: t.accounts.destination.address, amount: t.data.amount };
  }
  return UNSUMMED.has(type) ? { unsummed: accounts } : undefined;
}

function parsedMovement(parsed: unknown): Movement {
  if (!isRecord(parsed) || !isRecord(parsed.info)) throw new Error("The node returned an unreadable parsed token instruction");
  const { type, info } = parsed;
  const amount = type === "transfer" ? info.amount : type === "transferChecked" && isRecord(info.tokenAmount) ? info.tokenAmount.amount : undefined;
  if (amount === undefined) return typeof type === "string" && UNSUMMED_PARSED.has(type) ? { unsummed: stringsIn(info) } : undefined;
  if (typeof info.source !== "string" || typeof info.destination !== "string" || typeof amount !== "string") {
    throw new Error("The node returned an unreadable token transfer");
  }
  return { source: info.source, destination: info.destination, amount: BigInt(amount) };
}

/**
 * What the simulated transaction would move into `vault` (spec §5.4, §10.2): its SPL Token transfers into the vault, less
 * those out of it, its own and those its programs invoke. A pull from an allowance moves its tokens in an inner
 * instruction, which the static checks cannot see. Inner account indices refer to the static keys: there are no lookup
 * tables (spec §3.5). Throws on an inner instruction it cannot read, as the payer check does, and on a mint or a burn
 * that names the vault, whose effect a sum of transfers cannot tell.
 */
export function vaultReceipt(tx: InspectedTransaction, innerInstructions: unknown, vault: Address): bigint {
  if (!Array.isArray(innerInstructions)) throw new Error("The node's simulation returned no inner instructions");
  const movements: Movement[] = tx.instructions
    .filter((ix) => ix.programAddress === TOKEN_PROGRAM_ADDRESS)
    .map((ix) => compiledMovement((ix.accounts ?? []).map((meta) => meta.address), ix.data ?? new Uint8Array()));
  for (const group of innerInstructions) {
    if (!isRecord(group) || !Array.isArray(group.instructions)) throw new Error("The node's simulation returned an unreadable inner instruction group");
    for (const ix of group.instructions) {
      if (!isRecord(ix)) throw new Error("The node's simulation returned an unreadable inner instruction");
      const programIndex = asIndex(ix.programIdIndex);
      const program = typeof ix.programId === "string" ? ix.programId : programIndex !== undefined ? tx.accounts[programIndex] : undefined;
      if (program === undefined) throw new Error("The node's simulation returned an inner instruction without its program");
      if (program !== TOKEN_PROGRAM_ADDRESS) continue;
      if ("parsed" in ix) {
        movements.push(parsedMovement(ix.parsed));
        continue;
      }
      if (!Array.isArray(ix.accounts) || typeof ix.data !== "string") throw new Error("The node's simulation returned an unreadable token instruction");
      const accounts = ix.accounts.map((account) => {
        const resolved = typeof account === "string" ? account : tx.accounts[asIndex(account) ?? -1];
        if (resolved === undefined) throw new Error("The node's simulation returned an account index outside the transaction's keys");
        return resolved as Address;
      });
      movements.push(compiledMovement(accounts, getBase58Encoder().encode(ix.data)));
    }
  }
  let received = 0n;
  for (const movement of movements) {
    if (!movement) continue;
    if ("unsummed" in movement) {
      if (movement.unsummed.includes(vault)) throw new Error("a token instruction would change the vault's balance other than by a transfer");
      continue;
    }
    if (movement.destination === vault) received += movement.amount;
    if (movement.source === vault) received -= movement.amount;
  }
  return received;
}

import { fetchMaybeToken } from "@solana-program/token";
import { isSome, type Address, type Rpc, type SolanaRpcApi } from "@solana/kit";
import { fetchSysvarClock } from "@solana/sysvars";
import {
  allowanceAccounts,
  fetchMaybeRecurringDelegation,
  periodState,
  type AllowanceRef,
  type PeriodState,
} from "@lxfoundry/stint-subscriptions-client";

/** What the chain says about an allowance (spec §10.3). */
export interface AllowanceReport {
  readonly owner: Address;
  readonly delegation: Address;
  /** On the chain's clock. Absent when the owner has granted this key no such allowance, or has revoked it. */
  readonly period?: PeriodState;
  /** The owner's balance of the mint, in base units. */
  readonly ownerBalance: bigint;
  /**
   * What the owner's account lets the Subscription Authority move: its SPL Token delegated amount, or 0 when the account
   * has another delegate or none (S8: one delegate per token account).
   */
  readonly delegatedAmount: bigint;
}

/** Reads the delegation, the owner's balance and the chain's clock, at `confirmed`. */
export async function readAllowance(
  rpc: Rpc<SolanaRpcApi>,
  ref: AllowanceRef,
  config: { readonly abortSignal?: AbortSignal } = {},
): Promise<AllowanceReport> {
  const accounts = await allowanceAccounts(ref);
  const read = { commitment: "confirmed" as const, ...config };
  const [delegation, token, clock] = await Promise.all([
    fetchMaybeRecurringDelegation(rpc, accounts.delegation, read),
    fetchMaybeToken(rpc, accounts.ownerToken, read),
    fetchSysvarClock(rpc, read),
  ]);
  return {
    owner: ref.owner,
    delegation: accounts.delegation,
    ...(delegation.exists ? { period: periodState(delegation.data, BigInt(clock.unixTimestamp)) } : {}),
    ownerBalance: token.exists ? token.data.amount : 0n,
    delegatedAmount:
      token.exists && isSome(token.data.delegate) && token.data.delegate.value === accounts.subscriptionAuthority ? token.data.delegatedAmount : 0n,
  };
}

/** Why the allowance cannot fund a payment of `amount` now, or undefined when it can (spec §10.3). */
export function allowanceShortfall(report: AllowanceReport, amount: bigint): string | undefined {
  const period = report.period;
  if (!period) return `the owner ${report.owner} has granted this key no allowance, or has revoked it`;
  if (period.status === "expired") return "the allowance has expired";
  if (period.status === "notStarted") return "the allowance has not started yet";
  if (period.available < amount) {
    if (amount > period.perPeriod) return `the payment, ${amount}, is larger than the allowance's cap per period, ${period.perPeriod}`;
    return `the allowance for this period is used up: ${period.pulled} of ${period.perPeriod} pulled, ${period.available} left, ${amount} needed; the period ends at ${period.periodEnd}`;
  }
  if (report.ownerBalance < amount) return `the owner's account holds ${report.ownerBalance}, less than the ${amount} needed`;
  if (report.delegatedAmount < amount) {
    return "the owner's account no longer lets the allowance program move its tokens: its SPL Token delegate was changed or revoked";
  }
  return undefined;
}

- **The URL is checked first:** `isNodeUrl` refuses a URL that `fetch` would refuse. `fetch` quotes such a URL in its

- **Every error is cleaned:** what the node answers and what the transport throws go through `hideNodeUrl` before any
  caller sees them. A node may repeat the key it was given ("invalid api key …"), and the MCP server hands a tool's

```ts
import { createDefaultRpcTransport, createSolanaRpcFromTransport, type Rpc, type RpcTransport, type SolanaRpcApi } from "@solana/kit";
import { redactUrls } from "@lxfoundry/stint-x402";

/**
 * Whether `value` can be a node's URL (spec §9.1): an http or https URL that `URL` parses, as `fetch` will. A value with
 * a space in its host, no scheme or another scheme cannot. A problem never quotes the value: an RPC URL may carry an API
 * key.
 */
export function isNodeUrl(value: string): boolean {
  try {
    return /^https?:$/.test(new URL(value).protocol);
  } catch {
    return false;
  }
}

/** Shorter parts of a URL carry no key (`v2`, `rpc`), and hiding them would only garble a message. */
const SHORTEST_SECRET = 4;

/**
 * The parts of a node's URL that may carry a key: its user info, path segments, query values and fragment, as written
 * and decoded. For a URL that does not parse, the whole of it and each of its pieces between spaces.
 */
function secretParts(url: string): string[] {
  let raw: string[];
  try {
    const parsed = new URL(url);
    raw = [
      parsed.username,
      parsed.password,
      ...parsed.pathname.split("/"),
      ...parsed.search.slice(1).split("&").map((pair) => pair.slice(pair.indexOf("=") + 1)),
      parsed.hash.slice(1),
    ];
  } catch {
    raw = [url, ...url.split(/\s+/)];
  }
  const decoded = raw.map((part) => {
    try {
      return decodeURIComponent(part);
    } catch {
      return part;
    }
  });
  // Longest first, so that a part that holds another is hidden whole.
  return [...new Set([...raw, ...decoded])].filter((part) => part.length >= SHORTEST_SECRET).sort((a, b) => b.length - a.length);
}

/** `text` with every part of `url` that may carry a key hidden, wherever it appears, and every URL reduced to its scheme and host. */
export function hideNodeUrl(url: string, text: string): string {
  let hidden = text;
  for (const part of secretParts(url)) hidden = hidden.split(part).join("…");
  return redactUrls(hidden);
}

/**
 * A client of the node at `url` (spec §9.1) whose errors never carry what may be the URL's key. What the node answers in
 * a JSON-RPC error and what the transport throws go through `hideNodeUrl` before any caller sees them: a node can repeat
 * the key it was given ("invalid api key …"), and a failed request can quote its URL. `transport` is for tests.
 */
export function createNodeRpc(url: string, transport: RpcTransport = createDefaultRpcTransport({ url })): Rpc<SolanaRpcApi> {
  const hiding = (async (request: Parameters<RpcTransport>[0]) => {
    let response: unknown;
    try {
      response = await transport(request);
    } catch (error) {
      if (!(error instanceof Error)) throw new Error(hideNodeUrl(url, String(error)));
      error.message = hideNodeUrl(url, error.message);
      if (error.stack !== undefined) error.stack = hideNodeUrl(url, error.stack);
      throw error;
    }
    const answered = (response as { error?: { message?: unknown } } | null)?.error;
    if (answered && typeof answered.message === "string") answered.message = hideNodeUrl(url, answered.message);
    return response;
  }) as RpcTransport;
  return createSolanaRpcFromTransport(hiding);
}

async function readKeypair(deps: CommandDeps, path: string): Promise<KeyPairSigner> {

    throw new Error(`--keypair ${path}: the file cannot be read, or does not hold a keypair as a JSON array of 64 bytes`);

/**
 * `stint allowance grant | revoke | status` (spec §10.1). Devnet only: it checks the node's genesis hash before it sends
 * anything. The owner signs and pays the fee and the rent of the grant's accounts. Returns the exit code; problems are
 * printed, never a key's contents or the node's URL.
 */
export async function runAllowanceCommand(argv: readonly string[], deps: CommandDeps): Promise<number> {
  const [action, ...rest] = argv;
  let values: Record<string, string | boolean | undefined>;
  try {
    ({ values } = parseArgs({
      args: [...rest],
      options: {
        keypair: { type: "string" },
        owner: { type: "string" },
        agent: { type: "string" },
        "per-period": { type: "string" },
        period: { type: "string" },
        expires: { type: "string" },
        nonce: { type: "string" },
        "close-authority": { type: "boolean" },
      },
      strict: true,
    }));
  } catch (error) {
    deps.print(`${(error as Error).message}\n${USAGE}`);
    return 2;
  }
  const problems: string[] = [];
  const text = (name: string): string | undefined => (typeof values[name] === "string" ? (values[name] as string) : undefined);
  const needAddress = (name: string): Address | undefined => {
    const value = text(name);
    if (value === undefined || !isAddress(value)) problems.push(`--${name} must be an address`);
    return value !== undefined && isAddress(value) ? value : undefined;
  };
  const whole = (name: string, min: bigint, fallback?: bigint): bigint | undefined => {
    const value = text(name);
    if (value === undefined && fallback !== undefined) return fallback;
    if (value === undefined || !/^\d+$/.test(value) || BigInt(value) < min) {
      problems.push(`--${name} must be a whole number of at least ${min}`);
      return undefined;
    }
    return BigInt(value);
  };
  if (!["grant", "revoke", "status"].includes(action ?? "")) {
    deps.print(USAGE);
    return 2;
  }
  const agent = needAddress("agent");
  const nonce = whole("nonce", 0n, 0n);
  const mint = USDC_DEVNET.mint;
  let perPeriod: bigint | undefined;
  let period: bigint | undefined;
  let expiresAt: bigint | undefined;
  if (action === "grant") {
    perPeriod = whole("per-period", 1n);
    period = whole("period", 1n);
    if (period !== undefined && period > MAX_PERIOD_SECONDS) problems.push(`--period may be at most ${MAX_PERIOD_SECONDS} s, the program's limit`);
    const expires = Date.parse(text("expires") ?? "");
    if (Number.isNaN(expires) || expires <= Date.now()) problems.push("--expires must be an ISO 8601 date in the future");
    else expiresAt = BigInt(Math.floor(expires / 1000));
  }
  const ownerAddress = action === "status" ? needAddress("owner") : undefined;
  if (action !== "status" && text("keypair") === undefined) problems.push("--keypair is required");
  if (problems.length > 0) {
    deps.print(`${problems.join("\n")}\n${USAGE}`);
    return 2;
  }
  try {
    const genesis = await deps.rpc.getGenesisHash().send();
    if (genesis !== DEVNET_GENESIS_HASH) {
      deps.print(`The node reports genesis hash ${genesis}, which is not devnet's: nothing is sent`);
      return 1;

      return 0;

        owner,
        agent: agent!,
        mint,
        perPeriod: perPeriod!,
        periodSeconds: period!,
        expiresAt: expiresAt!,
        nonce: nonce!,

      deps.print(`granted: delegation ${accounts.delegation}, ${perPeriod} base units every ${period} s until ${new Date(Number(expiresAt) * 1000).toISOString()}`);
      deps.print(`transaction ${signature}`);
      return 0;
    }

    const signature = await deps.send(owner, revokeInstructions({ owner, delegation: accounts.delegation, ...(closeAuthority ? { closeAuthority } : {}) }));

    return 0;

    // A node's error can quote its URL, which may carry an API key: every URL is reduced to its scheme and host.
    deps.print(redactUrls(error instanceof Error ? error.message : String(error)));
    return 1;
  }
}

 * returns to the key before the clean-up empties it (spec §12.6). An earlier run that stopped half-way leaves them. Each
 * key's authority is found by its address. Its delegations are found by a `getProgramAccounts` filtered on the delegator,
 * on `scanRpc`, the endpoint that answers that method. The fee is the funding key's (`feePayer`); the held key signs.
 * Returns the problems, as the rest of the clean-up does.
 */
export async function revokeHeldAllowances(
  rpc: Rpc<SolanaRpcApi>,
  scanRpc: Rpc<SolanaRpcApi>,
  feePayer: KeyPairSigner,
  holders: ReadonlyMap<Address, KeyPairSigner>,
  send: SendOptions,

  const problems: string[] = [];
  const keys = [...holders.keys()];
  const authorities = await Promise.all(
    keys.map(async (owner) => (await findSubscriptionAuthorityPda({ user: owner, tokenMint: USDC_DEVNET_MINT }))[0]),
  );
  const found: { owner: Address; authority: Address }[] = [];
  for (let start = 0; start < keys.length; start += 100) {
    const batch = authorities.slice(start, start + 100);
    const { value } = await rpc.getMultipleAccounts(batch, { encoding: "base64", commitment: "confirmed" }).send();
    value.forEach((account, offset) => {
      if (account) found.push({ owner: keys[start + offset]!, authority: batch[offset]! });
    });
  }
  for (const { owner, authority } of found) {
    const signer = holders.get(owner)!;
    try {
      const delegations = await scanRpc
        .getProgramAccounts(SUBSCRIPTIONS_PROGRAM_ADDRESS, {
          encoding: "base64",
          commitment: "confirmed",
          filters: [
            // The IDL gives no size: the encoder's fixed size is the account's, 211 bytes.
            { dataSize: BigInt(getRecurringDelegationEncoder().fixedSize) },
            // An address is the base58 text of its 32 bytes.
            { memcmp: { offset: DELEGATOR_OFFSET, bytes: owner as unknown as Base58EncodedBytes, encoding: "base58" } },
          ],
        })
        .send();
      const instructions = [
        ...delegations.flatMap(({ pubkey }) => revokeInstructions({ owner: signer, delegation: pubkey })),
        getCloseSubscriptionAuthorityInstruction({ user: signer, subscriptionAuthority: authority }),
      ];
      // The fee is the funding key's: the held key may hold no SOL by now, and its rent comes back to it.
      await sendInstructions(rpc, feePayer, instructions, send);
    } catch (error) {
      problems.push(`revoking the allowances of ${owner}: ${describeError(error)}`);
    }
  }
  return problems;
}
```

A key with many delegations could exceed one transaction's size: the harness grants at most one per owner, and a run
uses a handful of owners.

`conformance/src/scenarios/12-allowance-funding.ts`:

```ts
import type { Address } from "@solana/kit";
import { createStintClient, type Policy } from "@lxfoundry/stint-client";
import { fetchMaybeSession } from "@lxfoundry/stint-program-client";
import { fetchMaybeRecurringDelegation } from "@lxfoundry/stint-subscriptions-client";
import { associatedTokenAddress } from "@lxfoundry/stint-x402";
import { expectEqual, expectTrue } from "../assert.js";
import { awaitClose } from "../closes.js";
import { closePollMs, refusalOf, sessionSeconds } from "../helpers.js";
import { openOffers } from "../payments.js";
import { readUntil } from "../reads.js";
import { describeError } from "../runner.js";
import type { ScenarioContext } from "../types.js";

/** The limits the scenarios use (helpers.ts's `buyerClient`), so that only the allowance's cap refuses a payment. */
const POLICY: Policy = { maxRate: 10_000n, maxPerSession: 1_000_000n, budget: { amount: 1_000_000n, periodSeconds: 3_600 } };

/**
 * Scenario 12 (spec §10, §12.7): an owner grants the agent's key a recurring delegation, and the agent's sessions are paid
 * from it. Pulled from the owner: the open and the top-up take the owner's USDC, and the agent holds none. Refunded to the
 * owner: an early close returns the unused part to the owner, and the period's count of what was pulled stays where it
 * was. Refused over the cap: a payment past the period's cap is refused by the chain, takes nothing and locks nothing; a
 * client with a node refuses it before signing.
 */
export async function allowanceFunding(context: ScenarioContext): Promise<void> {
  const allowance = context.allowance;
  if (!allowance) throw new Error("Scenario 12 needs the harness to grant an allowance (context.allowance), as the local and devnet targets do");
  const { offer } = await openOffers(context.gateUrl);
  const rate = BigInt(offer.extra.rate);
  const first = sessionSeconds(context.target, 20);
  const extra = sessionSeconds(context.target, 10);
  // The cap covers the open and the top-up with 5 s to spare. The third payment is larger than what is left even after
  // the open alone (`extra + 5` s), so a node that answers from behind still shows it over the cap.
  const third = extra + 10;
  const perPeriod = rate * BigInt(first + extra + 5);
  const funded = rate * BigInt(first + extra + 40);
  const grant = await allowance.grant({ usdc: funded, perPeriod, periodSeconds: 3_600 });
  try {
    const owner = grant.owner.signer.address;
    const usdcOf = async (account: Address): Promise<bigint> => {
      const { value } = await context.rpc.getAccountInfo(account, { encoding: "base64", commitment: "confirmed" }).send();
      if (!value) return 0n;
      return BigInt((await context.rpc.getTokenAccountBalance(account, { commitment: "confirmed" }).send()).value.amount);
    };
    // A node can answer from behind right after it reported a transaction confirmed (spec §12.2): every read that follows
    // a payment is retried until it shows what the scenario expects, and the assertion reports what it last found.
    const ownerBalance = (expected: bigint) => readUntil(context.readRetry, () => usdcOf(grant.owner.usdcAccount), (amount) => amount === expected);
    const pulled = (expected: bigint) =>
      readUntil(
        context.readRetry,
        async () => {
          const read = await fetchMaybeRecurringDelegation(context.rpc, grant.delegation, { commitment: "confirmed" });
          return read.exists ? read.data.amountPulledInPeriod : undefined;
        },
        (amount) => amount === expected,
      );
    const client = createStintClient({ signer: grant.agent, policy: POLICY, allowance: { owner, nonce: grant.nonce } });
    const ownerStart = funded;
    expectEqual(await ownerBalance(ownerStart), ownerStart, "the owner holds what it was funded with");

    // Pulled from the owner. A connection holds the session from the open to the close: the gate closes a session that has
    // had none for its idle close, and the reads below take seconds on devnet.
    const session = await client.open(context.gateUrl, { seconds: first });
    const deposit = session.cost;
    const holding = await session.connect();
    holding.on("error", () => {});
    try {
      const readSession = () => fetchMaybeSession(context.rpc, session.id, { commitment: "confirmed" });
      const opened = await readUntil(context.readRetry, readSession, (read) => read.exists);
      expectTrue(opened.exists, "the session exists on-chain after the open");
      if (!opened.exists) return;
      expectEqual(opened.data.refundOwner, owner, "the session's refund owner is the allowance's owner");
      expectEqual(opened.data.authority, grant.agent.address, "the session's authority is the agent");
      expectEqual(await ownerBalance(ownerStart - deposit), ownerStart - deposit, "the open is pulled from the owner's account");
      const agentToken = await associatedTokenAddress(grant.agent.address, opened.data.mint);
      expectEqual((await context.rpc.getAccountInfo(agentToken, { commitment: "confirmed" }).send()).value, null, "the agent has no USDC account at all");
      expectEqual(await pulled(deposit), deposit, "the period counts the open");

      // The top-up is pulled too. `session.cost` counts everything the session holds: the deposit and the top-up.
      const toppedUp = await session.topUp({ seconds: extra });
      const held = session.cost;
      expectEqual(held, deposit + toppedUp.cost, "the session holds the deposit and the top-up");
      expectEqual(await ownerBalance(ownerStart - held), ownerStart - held, "the top-up is pulled from the owner's account");
      expectEqual(await pulled(held), held, "the period counts the open and the top-up");

      // Refunded to the owner, and the period's count stays.
      await session.close();
      const { event } = await awaitClose(context.rpc, session.id, context.readRetry, 15_000, "the close is on-chain", closePollMs(context.target));
      expectTrue(event.refunded > 0n, "closing early refunds something");
      const afterClose = ownerStart - held + event.refunded;
      expectEqual(await ownerBalance(afterClose), afterClose, "the refund goes to the owner's account");
      expectEqual(await usdcOf(agentToken), 0n, "nothing reaches the agent");
      expectEqual(await pulled(held), held, "a refund does not restore the allowance");

      // Refused over the cap, by the chain: nothing taken, nothing locked, nothing counted.
      const budget = client.remainingBudget();
      const refused = await refusalOf(client.open(context.gateUrl, { seconds: third }));
      expectEqual(refused?.status, 402, "a payment over the cap is refused with 402");
      expectEqual(refused?.reason, "simulation_failed", "a payment over the cap is refused as simulation_failed");
      expectTrue(/allowance/.test(refused?.message ?? ""), "the refusal says that an allowance may be the cause");
      expectEqual(await ownerBalance(afterClose), afterClose, "the refused payment takes nothing from the owner");
      expectEqual(client.remainingBudget(), budget, "the refused payment locks nothing");
      expectEqual(await pulled(held), held, "the refused pull is not counted");

      // A client with a node refuses it before signing.
      const checking = createStintClient({ signer: grant.agent, policy: POLICY, allowance: { owner, nonce: grant.nonce }, rpc: context.rpc });
      const early = await refusalOf(checking.open(context.gateUrl, { seconds: third }));
      expectEqual(early?.status, undefined, "a client with a node refuses before sending anything");
      expectTrue(/allowance for this period is used up/.test(early?.message ?? ""), "it says that the period's allowance is used up");
    } finally {
      holding.terminate();
    }
  } finally {
    // A failed revoke must not hide the scenario's own outcome. On devnet, the clean-up revokes whatever is left.
    await allowance.revoke(grant).catch((error: unknown) => console.error(`scenario 12: the revoke failed: ${describeError(error)}`));
  }
}
```

**The arithmetic:**
- `session.cost` counts everything the session holds through this client, the opening deposit and each top-up (spec
  §9.4). The scenario keeps the deposit apart (`deposit`), and compares the owner's balance and the period's count with
  `session.cost` after the top-up.
- The cap is `rate × (first + extra + 5)`. The third payment costs `rate × (extra + 10)`: more than the 5 s left after the
  top-up, and more than the `extra + 5` s left after the open alone. So it is refused whatever the target's
  `sessionSeconds` adds, and by the client with a node even if that node answers from behind. On `local` the cap is
  35 s of the rate and the third payment 20 s; on devnet, 55 s and 30 s.
- **Reads:** every read after a payment retries until it shows the expected value (`ownerBalance`, `pulled`,
  `readUntil`). The checking client's own read before signing is single. The third payment's size is what keeps that
  read safe.
- **The idle close:** the connection is opened right after the open and held until after the close. The gate arms its
  idle close (10 s) at the open, and on devnet the reads between the open and the top-up take longer than that.
